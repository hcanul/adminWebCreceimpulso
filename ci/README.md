# Integración con Jenkins

El Jenkinsfile comprueba Laravel mediante PHPUnit y las tres apps Quasar mediante tipos, ESLint y compilación SPA. Usa Node 24.22.2 y pnpm 12.10.1 en .tools, y los lockfiles de cada aplicación. Para admin-web instala también las dependencias de src-electron sin descargar el ejecutable de escritorio. Para client-app y staff-app instala las dependencias de src-capacitor antes de compilar. Los fallos de PHPUnit mantienen el resultado final en FAILURE y permiten verificar también los frontends.

El agente bussix-linux debe disponer de PHP 8.2 o superior, Composer, intl, SQLite, mbstring, XML, cURL y ZIP. El agente compartido ya utiliza creceimpulso-ci-check:20261118 con intl; se conserva el contenedor anterior detenido para recuperación.

El trabajo apunta a https://github.com/hcanul/adminWebCreceimpulso.git y a main. Cada cambio, incluidos los merges, publica en pruebas después de pasar CI. El sondeo está configurado cada diez minutos. Cada proyecto ocupa un solo ejecutor y las apps se procesan secuencialmente.

Las compilaciones usan QCLI_API_URL=https://pruebas.creceimpulso.com/api. Los artefactos web se conservan para revisión; el paquete cPanel requiere que las verificaciones pasen. Main publica por FTPS y solicita las migraciones mediante el cron privado después de pasar CI. El parámetro DEPLOY_CPANEL permite forzar una publicación manual; es falso por defecto. Véase ci/cpanel/README.md.

El destino solicitado es pruebas.creceimpulso.com, con PHP 8.3.27 informado por el usuario. Se verificó FTPS explícito en el puerto 21 de svgm374.serverneubox.com.mx con certificado válido, alias del mismo servidor que ftp.creceimpulso.com. La credencial creceimpulso-pruebas-ftps está guardada en Jenkins. El dominio ya resuelve al hosting y su carpeta pública es /home/creceimp/pruebas.creceimpulso.com. Se creó la base vacía creceimp_pruebas. Un diagnóstico privado mediante cron verificó PHP 8.3.36 e intl, pdo_mysql y zip. La configuración de MySQL fue comprobada desde el hosting y el cron de despliegue está registrado cada cinco minutos. La publicación y comprobación HTTP se verifican con la ejecución que activa DEPLOY_CPANEL.

La primera validación usó e7b947f de GitHub y conservó los cambios pendientes de la carpeta original. Los dos fallos de ClientPushTest correspondían a pruebas desactualizadas: falta de installation_id y expectativa anterior de revocación limitada a sesión. Se alinearon con el contrato documentado de revocación de dispositivos de la cuenta y se reforzó el aislamiento respecto a otra cuenta. La suite completa pasó: 187 pruebas, 2228 aserciones. CI crea su propio .env de pruebas desde .env.example para evitar avisos; las variables de SQLite y claves efímeras se inyectan desde Jenkins.

Jenkins quedó configurado con Branch Specifier `*/main`. Los merges y pushes a main se detectan mediante el sondeo y publican en el entorno de pruebas únicamente después de pasar todas las verificaciones; no requieren marcar DEPLOY_CPANEL. La solicitud llega al cron privado de cPanel, que ejecuta respaldo y migraciones cada cinco minutos. El alta inicial del administrador se realiza por separado, una sola vez, mediante un archivo privado confirmado por su propietario.
